MONEY MAP - v2.0.3.59
Upload: Money_Map.html + sw.js  (web files only, no APK needed)
This build supersedes the v2.0.3.58 zip and carries every change from v50 to v59.

====================================================================
WHAT THIS RELEASE IS
====================================================================
This is the clean-up you approved: the old profile-editing patches that
no longer worked have been REMOVED from the file, not layered over.
One owner now handles the profile flow, the back gesture, the idle
re-lock, the notification routing, the loan and goal cards and the
financial health card.

Removed for good (four dead generations of patch):
  1. v54's capture listener on the Settings photo. It ran
     preventDefault + stopPropagation before anything else, which is why
     tapping the photo "first showed the edit icon and then switched to
     camera / gallery", and why the name never became editable.
  2. v54's claim on openEditProfile, plus its name screen that was built
     INSIDE the settings page - underneath the overlay, so invisible.
  3. v56's "what do you want to edit" chooser card.
  4. v58's whole edit screen, its photo viewer and its back handler.
  5. v54's loan and goal captions, which were rewritten on their own
     timers and always won the race, plus the duplicate
     "From / Taken / Original" row inside the open card.

Nothing in the app's own logic was touched: money maths, budgets,
assets, backup, encryption, notifications planning, theming and the
app-lock all run on the same code as before.

====================================================================
FIXED IN THIS BUILD
====================================================================
PROFILE EDITING (Settings)
- The pencil in Settings now opens ONE screen: the picture with a camera
  badge, and the name row. Nothing else from Settings shows behind it.
- Tapping the name opens the name screen on its own; saving writes the
  name and returns to the edit screen; the new name shows immediately.
- The name row no longer carries an arrow or a pencil icon.
- Tapping the camera badge raises a card from the bottom: take a photo,
  choose from gallery, remove image.
- Tapping the picture itself opens it square, on its own, with a pencil
  at the top right and "Remove image" underneath.
- Back button and back gesture now unwind one step at a time:
  picture -> edit screen -> Settings, with the nav bar back in place.
  It no longer throws you out to the Overview, and it no longer closes
  the whole app.

NOTIFICATIONS
- The shell calls the app with (route, id) - route first. The old code
  read them the other way round, so EVERY notification landed on the
  Overview and the real routing never ran. Now the test notification
  opens the Overview with the nav bar intact, savings notifications open
  Goals, loan reminders open Loans, and an unknown id falls back to the
  route the shell asked for instead of guessing.
- Any stale "nav bar hidden" state left by the 3-dots menu is cleared
  when a notification opens the app.

FINANCIAL HEALTH CARD
- The year pill now builds its list from real transactions only, and it
  no longer rewrites the app-wide month filter. Closing the card puts
  the top-of-screen period back exactly as it was.
- The card is built in the same tick as it opens, so it no longer shakes
  after expanding.
- Each item shows its own figure and its score on one line, ending with
  average monthly surplus (which carries no points), then one short line
  of explanation. The progress bars are gone.

LOANS AND GOALS
- The closed loan card shows who it came from and when it was taken. The
  balance left is no longer on the closed card - it shows once the card
  is open.
- A settled loan keeps the "Fully paid" pill in place of the ring.
- The open card no longer repeats what the closed card already said.
- The same de-duplication is applied to goals, and the goal "Completed"
  line with its month is untouched.

IDLE RE-LOCK
- The one-minute rule works again. The old fix replaced a function the
  real listeners never called, and the PIN check it depended on had been
  removed in v55. It now re-locks on the real visibility event and it
  accepts a hashed PIN as a PIN.
